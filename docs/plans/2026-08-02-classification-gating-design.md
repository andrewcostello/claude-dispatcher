## 0. Threat model and proportionality (NORMATIVE — core RATIFIED 2026-08-02; §0.2(c), §0.3–0.5 amendments pending ratification)

### 0.1 Deployment and adversaries (RATIFIED)
Single operator: one human owns the machine, repos, CLI, and the GitHub account with merge rights. LLM agents author task YAML, code, branches, PR bodies, and invoke tools inside worktrees. In scope: (1) **agent-authored content** — capable, non-malicious-by-assumption, unreliable and optimizing; untrusted input to every gate; (2) **honest misconfiguration**; (3) **process faults** (crashes, restarts, concurrency, ref movement between read and act). Out of scope: a malicious human with shell access — no in-process mechanism is meaningful against them. Provenance = channel, not cryptographic identity.

### 0.2 Agent capability (stated honestly)
Agents hold full git/filesystem capability in the repo clone and can push to unprotected remote refs (proven: tests/fixtures/fake_claude.py:172–198; direct-to-base treated as success today, orchestrator.py:3231). Therefore **no protected effect and no gate input may depend on local repo state, run dirs, journal, task YAML, or PR bodies remaining agent-untouched — all of these are mirrors.** Authority lives only in:
- **(a) origin-side state agents cannot rewrite** — refs behind no-bypass protection, and GitHub's own event/audit surface (push/merge events, review records: writable-once by API action, not rewritable with a push credential);
- **(b) dispatcher process memory within one invocation**;
- **(c) the operator's live CLI channel** (flags typed at dispatch; interactive confirmations) — **with this channel-level qualifier under SHARED credentials (round 8, claude; supersedes the command-level wording; PENDING OPERATOR RATIFICATION):** an in-scope agent on the same machine, OS user and credential can pty-spawn any dispatcher command and answer its prompts, so under SHARED, *every* channel-(c) interaction — HUMAN_REQUIRED consent, reconcile/hold release, cold-start base confirmation, unverified-evidence acceptance, suppression, approver-set declaration, and dispatch flags themselves — is **operator-attested, not machine-enforced**. Run reporting states this sentence. Machine enforcement of any channel-(c) interaction requires SEPARATED with verified credential isolation (§0.3 bar). Mitigations under SHARED: origin-side visibility of every resulting effect, and §0.1's non-malicious assumption. The launder path (agent-authored wrappers) is the same residual by another door.

### 0.3 Credential model (round 5, claude M2; OPERATOR RULING on machine accounts)
The trust statements above are statements about **credentials**, not git. Two modes, probed at preflight:
- **SHARED** (today): agents inherit the operator's push credential. Consequences, stated: origin cannot distinguish agent pushes from dispatcher/operator pushes; ref-level protection binds *everyone*; the ELEVATED GitHub-approval path is secured **only by GitHub's no-self-approval rule on the mono-token — an accident now made normative**: preflight warns if any additional write-capable identity exists undeclared. Preflight verifies what the API exposes (token scopes, ruleset bypass actors — the ambient credential must not be a bypass actor or admin) and **WARNS** that credential separation is absent.
- **SEPARATED** (recommended good practice — operator ruling): agent sessions use a machine-account credential. Rulesets can then scope by actor: hold-ref and state writes restricted to the operator credential; door-0 attribution by pusher identity; ELEVATED approvals verifiable by actor. SEPARATED is a **verified predicate, not a label** (round 9, grok: a machine account whose session still inherits `GITHUB_TOKEN` gives a false sense of enforcement while reporting claims SEPARATED): preflight records it only when ALL pass — (1) no ambient operator token readable from the agent session context (env, gh config, credential helpers under the agent UID); (2) agent security domain ≠ operator security domain — distinct OS users by default; a same-UID setup can NEVER record SEPARATED on the credential-delivery method alone (round 10, codex: a same-UID sibling process reads `/proc/<pid>/environ`, so per-command injection without domain separation is agent-recoverable), and qualifies only under a fully specified, probed isolation profile (/proc, ptrace, inherited fds, credential helpers, terminal, executable provenance) which this design does not yet define — until then, same-UID ⇒ SHARED; (3) the agent credential's API `viewer` identity ≠ the operator identity; (4) neither credential is a ruleset bypass actor. Any predicate failing or unprobeable ⇒ record SHARED — never a soft SEPARATED; the probe evidence is journalled at genesis, and T28 is those predicates as a **frozen pass/fail command checklist** — env scan per UID; `gh auth status` under each identity; credential-helper and token-file ACLs; no shared docker.sock or group-readable stores — with `HUMAN_IDENTITY_ENFORCED` anywhere in this design requiring T28 green (round 11, grok: a partial probe mints false assurance). SEPARATED closes the residuals §6.0 names.

### 0.4 Base protection: PREVENT / DETECT (OPERATOR RULING — proportional to declared stakes)
- **PREVENT** — required when the pinned rule table contains `financial: true` or `human_pr_gate`-capable rules: preflight verifies a no-bypass ruleset on each protected base; refuses to start without it (`--allow-unprotected-base` = explicit journalled override).
- **DETECT** — otherwise: run proceeds with a loud preflight warning; `base_protection: ABSENT` in genesis; door 0 in detect-and-hold. Stated residuals: the push→detection window (hazardous where deploy checkouts track the base, e.g. Tilt on `main`); ABA restore defeats OID comparison (accepted: force-push restore is not an accident).

### 0.5 Proportionality rule
A mechanism is accepted when it defends against in-scope sources; rejected, with the finding cited, when it defends only against out-of-scope ones. Signed overrides, external trust roots, tamper-proof local audit: deferred (upgrade path: SEPARATED mode first, then multi-operator identity).

### 3.1 Closed runtime sum

## 12. Pass criteria (full text)
The design-reviewer role is adversarial by instruction; zero findings is not the bar. **Pass** = no seat reports a BLOCKING that is (a) a spec incompleteness or internal contradiction, (b) a fail-open within §0's ratified model, or (c) a false factual claim about current code (checked against the stated baseline). Findings requiring capabilities §0 defers are upgrade-path items. MAJORs are dispositioned (accepted into spec or rejected with §0 rationale) before implementation; MINORs at implementation time. The document carries T26 itself. **Harness rules (normative here; §10 points at them):** every parametrised seal includes ≥1 deny row (T6); every seal ships its revert-falsification in the PR; T26 is the doc lint — citations resolve at the stated baseline, the §10 index is complete and semantics-free, §-references resolve, and superseded disposition rows carry their markers; **retired identifiers (`AuthoritySnapshot`, `LegacyNoConfig`, `MOVED_TO_HOLD`, `integrity_hold` as an event name, `FOREIGN_OBSERVED`, `AuthorizedBaseTransition`, `request_id`, …) may appear only inside §11's tables, version-history notes, and retirement/supersession annotations — never as a live mechanism** (round 18, claude + codex: v18's wording was unsatisfiable — the sentence that retires a name necessarily names it). **The implementation plan's PR0 lands the FSM artifact and T26-as-CI BEFORE any feature code — the generated §6.0 tables and §9 unions come from it (round 15, grok: without that ordering, v16+ re-earns edit-artifact BLOCKINGs mechanically). The implementation plan MUST land the machine-readable artifacts as CI gates (round 12, codex): `lifecycle_fsm` (generating Apply/reducers/diagrams for sections A and B), the `panel_aggregate` spec, the classifier frame/wrapper schema with golden vectors, the AST allowlists (T8/T9), and enum-exhaustiveness lints — prose lint alone has demonstrably not held. The same plan defines `BoundaryError{code, phase, retriability, operator_action}` with exhaustive CLI/metric mappings (round 13, codex: `FailureKind` covers classifier outcomes only, not CAS conflicts, illegal transitions, or stale epochs), and the generated artifacts regenerate this document's own tables (round 13, claude: a schema-checked FSM would have rejected both v13 BLOCKINGs before any reviewer saw them).**
