### Deviations from the scaffold's ruled mechanics, and why

* **Unknown-nonce failures are keyed `unknown:<detail>`, not
  `unknown:<journal_path>`.** `publish_pin_from_genesis(payload, *, source,
  detail)` carries no journal path; adding a parameter changes the
  fingerprint `compare_signatures` checks, which the BODIES gate refuses.
  Both call sites build `detail` from the run id and the journal path only
  (`journal._anchor_detail`), so the ruled property — repeats on one journal
  collapse, two journals do not — holds by construction of the callers, not
  of the publisher. For W2-1-4: either add `journal_path` to the signature
  (a scaffold-level change) or ratify the indirection.
* **Member existence is answered before the gate.** The scaffold's loader
  docstring said the two `exists()` checks "become `render`'s
  missing-member refusal". Two legacy seals (`test_build_review_prompt_
  unknown_family_raises`, `test_unknown_domain_fails_loudly_and_lists_what_
  exists`) require `FileNotFoundError`, and `PromptProvenanceError` is a
  `RuntimeError`. The check reads NAMES off the same snapshot — no second
  walk, no bytes rendered — so constraint 1 is intact and a packaging error
  stays a packaging error regardless of anchoring.
* **Registry rows stay `file:line symbol`.** 2c recommended re-keying by
  file + symbol; its own claude finding shows the 2c seal's `_ROW` regex is
  SEALS-owned and every row would go red. Lines: 393 / 144 / 121 / 195;
  `entry_point_row(file)` gives each entry point its row so the line lives in
  one place.
