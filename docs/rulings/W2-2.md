## The move/rename boundary: the gate may be wrong about a MOVE, and only toward refusal

The question the contract could not dodge: to a per-file comparator, a
legitimate MOVE of a sealed symbol into a new file and an illegitimate
WIDENING arriving from a new file are the same event — a deletion in one file
and an added symbol in another. One of them the gate is allowed to be wrong
about.

**Decided:** the gate is allowed to be wrong about the **move**, and only in
the direction of **refusing** it. A branch that moves a sealed symbol between
files stays VIOLATION, exactly as it is refused today: the per-file loop
reports every symbol of the file it left with `after=None`, and the fold
(`branch_surface.compare_surfaces`, clause 3) stays silent on a pure move so
the same event is never reported twice. A widening is the thing the gate may
never be wrong about: a false negative there is the bypass W2-2 exists to
close, and it is the one direction with no reviewer behind it.

**Decided against: forgiving a removal paired with an identical addition
elsewhere** (git rename detection, or fingerprint-equality matching across
files). The decisive measurement is TS-3 below — move, then widen the moved
copy from a third file. The fold reports NOTHING on that branch: the moved
declaration is a NEW key at head, clause 1 ("an added key is not a change",
the rule this unit may not reverse) gives it no base to compare against, and
the augmentation of `./bet2` merges into a space that did not exist at base.
The per-file removal from `bet.ts` is the only thing standing between that
branch and CLEAN. Forgiving the move therefore reopens the bypass one hop
away from where it was closed. TS-5 makes the same point without a third
file: git pairs the deletion with a widened copy at 75 % similarity, and any
similarity threshold is a knob the branch author sets.

**Decided against: a symbol KEY that survives a move** (W2-2-1's contract
question). It is the only design that could tell a move from a widening, and
it would need identity carried across files in both the per-file loop and the
fold — a redesign of `SymbolKey` and of `compare_signatures`' per-file
contract, which is a scaffold unit, not a ruling. It also does not change the
answer: a moved-and-widened symbol would still have to be refused, so the
design changes the *message* ("moved" rather than "removed"), not the verdict.

**What it costs.** A body cannot re-home a sealed symbol in ANY spelling —
not by moving the file, not by leaving a re-export or re-import at the old
location. Measured: the re-export variant (TS-4) still reports `i:Bet`
removed and `k:export/i:Bet` changed; the re-import variant (PY-2) still
reports `Wallet` and `Wallet.debit` removed. The price per honest move is
one escalation, and it is the right escalation: under the contract-first
rules a move of a sealed symbol changes the import path of every dependent,
which makes it a `## Deviation` of kind `shared-contract` — landed by the
scaffold or operator who re-seals it, not by a body under its own gate. The
expected rate is near zero: bodies fill holes in files the skeleton placed,
and moving one is the silent redesign rule 1 forbids.

Role.BODIES)` on this tree (`59b6e10`, parser vendored), one throwaway

for moves (three in one feature would do) justifies revisiting the
*escalation path* — a scaffold-side move helper — never the refusal.

## Module-ness: an unprovable `.ts` file reads UNDETERMINED, and that stands

**Decided:** `build_surface`'s routing default is upheld. A changed TypeScript
file with no key-level proof of being an external module has its declarations
routed to the global space, which is unread, which is UNDETERMINED — never
CLEAN. Not softened in `build_surface`, which is where the amendment doc said
the softening would have to go.

**Decided against** routing an unproven file's declarations to its own space:
that is the two-scripts-declaring-one-interface bypass, and "we do not know
whether this is a module" is exactly the unknown input this project denies
on. The fail-open shape was refused for `merge_base` in round 3 and it is the
same shape here.

**Measured:** the fingerprinter puts the `export` modifier in the fingerprint
VALUE — `export interface Bet {…}` keys as `i:Bet` — so an ordinary exported
declaration is NOT proof; W2-2-2's fixtures needed `export type { Bet };` to
be provable. This repository has no `.ts` file, so the cost today is zero
here. In a TypeScript consumer, every body branch touching a file spelled the
ordinary way reads UNDETERMINED for BODIES.

**What would change it:** nothing softens the default. The cost is retired by
reporting `is_module` (`ts.isExternalModule`) from the helper, or keying the
export modifier — both on the floor (globs 3 and 12) and therefore a scaffold
unit of their own. The trigger to commission it is the first TypeScript
consumer's bodies wave, not a ruling.

## The closure is read over HEAD surfaces only (body's report, item 5) — upheld

A branch that deletes an augmentation from an existing file whose target is
not in the diff leaves the base `s:` key unresolved, and the fold answers
UNDETERMINED. Upheld: a deleted augmentation NARROWS a merged interface, which
is a contract change that deserves a reviewer, and UNDETERMINED is the fail-
closed answer to a space the fold could not bound. Reversal trigger: an honest
branch measured hitting it; the fix would extend `closure_request` to base
surfaces, which is body work under a new seal, not a driver change.
